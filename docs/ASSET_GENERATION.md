# 素材生成:評估與做法

AI 助手原本只能「用畫的」:它寫出 SVG 向量圖或像素格,編輯器轉成圖層。這對剪影、漸層、
幾何、像素風很好,但畫不出繪畫或照片質感的天空、風景、角色、材質。這份文件評估讓助手
**自己生成點陣圖素材**的幾種做法,說明目前接上的是哪一種、為什麼,以及還沒解決的地方。

## 問題的核心

生成一張好看的圖很容易,難的是**分層桌布需要的圖**:

1. **每一層是獨立的圖,但要屬於同一個世界。** 同樣的光線、配色、筆觸。分別下提示詞生成的五張圖,
   風格通常對不起來。
2. **除了最遠的一層,其他都要去背。** 而且被前景擋住的部分也要畫出來,因為手機傾斜時會露出來。
3. **不能從一張完成的圖直接拆。** 拆出前景之後,背景上會留下一個洞。

所以評估的重點不是「哪個模型畫得最漂亮」,而是「哪個做法能產出風格一致、可去背、沒有破洞的多張圖」。

## 評估過的做法

| 做法 | 風格一致 | 去背 | 被遮住的部分 | 成本 | 結論 |
|---|---|---|---|---|---|
| A. 模型自己寫 SVG / 像素格 | 好(同一個模型同一次規劃) | 天生透明 | 模型自己會畫到畫布外 | 只有對話 token | **保留**,作為基礎 |
| B. 每層各下一次提示詞生成 | 差 | 視模型 | 可在提示詞要求 | 每層一張圖 | 不採用 |
| C. 先生成一張「風格母片」,每層生成時都帶著它當參考 | 好 | 視模型 | 可在提示詞要求 | 母片 + 每層一張 | **採用** |
| D. 生成一張完成圖,用景深圖切層,再補洞 | 最好(本來就是同一張) | 切出來的邊緣要處理 | 需要補畫(inpainting) | 一張圖 + 每層一次補畫 | 下一步,見後述 |
| E. 本機跑擴散模型 | 可控 | 可外掛去背模型 | 可補畫 | 免費但要顯示卡 | 不適合純網頁工具 |

**為什麼是 C 而不是 D:** D 的結果理論上最一致,App 裡也已經有景深模型(Depth Anything)。
但它需要可靠的補洞,而且切層邊緣(頭髮、樹葉)的品質取決於景深圖精度,做壞了比 C 明顯。
C 完全靠現成的圖片模型就能做,而且現在的圖片模型都能吃參考圖,所以先接 C。

## 兩家圖片模型的差別

| | Gemini 圖片模型 | GPT Image |
|---|---|---|
| 透明背景 | **不支援**。官方文件明說,建議改用純色背景 | **原生支援**(`background: "transparent"`) |
| 參考圖 | 最多約 14 張 | 透過 edits 端點帶入 |
| 直式輸出 | 9:16,可到 2K、4K | 1024×1536,也可自訂尺寸 |
| 每張約略價格 | US$0.03 – 0.13(依模型與解析度) | 依 token 計價,中等品質約數美分到十幾美分 |
| 需要 | Gemini API 金鑰(圖片模型沒有免費額度) | OpenAI API 金鑰,且帳號要通過組織驗證 |
| 用 ChatGPT 登入可用嗎 | 不相關 | **不行**,官方的登入流程不開放圖片生成 |

結論:**要去背素材最乾淨,用 GPT Image;要便宜、要高解析度背景,用 Gemini。** 兩者都接上了,
在「AI 設定 → 素材生成」選擇。對話模型和圖片模型各自獨立,例如可以用 Claude 規劃、用 Gemini 生圖。

### Gemini 的去背怎麼做

因為不支援透明,去背圖分兩步:

1. 生成時在提示詞後面加上要求:主體完整、放在**純綠色(#00FF00)**背景上、不要陰影不要漸層。
   如果描述裡提到綠色的東西(樹、草、竹、森林…),改用**洋紅色(#FF00FF)**,避免把主體也去掉。
2. 編輯器自己做色鍵去背:取四個角落的顏色當背景色,**從畫面邊緣往內擴散**,碰得到的背景色像素變透明;
   邊緣一圈做漸層,並把背景色從半透明像素裡扣掉,避免邊緣發綠。
   - 主體內部剛好接近背景色的區塊(例如綠背景上的綠眼睛)因為從邊緣碰不到,會保留下來。
   - 被主體包住的背景(手臂和身體之間、圓環中間)從邊緣也碰不到,所以另外用更嚴格的標準判斷:
     顏色幾乎等於背景色的像素一律去掉。

限制:半透明的東西(玻璃、煙、髮絲)去不乾淨;主體上顏色幾乎等於背景色的地方仍會被挖洞;
模型偶爾不聽話,背景不是純色。這時助手可以用 `remove_background` 指定顏色和容許度重做,或重新生成。

## 接上去的方式

助手多了四個工具(前三個不需要圖片模型也能用):

- `add_image_layer`:把任何一張圖(你附的參考圖或生成的圖,編號 `ref:N`)整張放成圖層。
- `view_image`:讓模型看某一張圖,透明處顯示棋盤格。
- `remove_background`:把純色背景變透明,結果成為新的 `ref`。
- `generate_image`:生成一張圖並登記為下一個 `ref`。參數有描述、形狀(直/方/橫)、是否去背、
  要保持一致的參考圖(最多 3 張)。只有在設定裡選了圖片模型且填了金鑰時才會出現。

系統提示裡教模型的流程:

1. 先生成整個場景當**風格母片**,固定配色、光線和畫風。它通常不直接當圖層。
2. 生成**最遠的一層**:只有天空和遠景、填滿畫面,帶著母片當參考。
3. 每個較近的元素**單獨生成、去背**,同樣帶著母片,並要求畫出會被擋住的部分。
4. 用 `add_image_layer` 由遠到近放上去,再照常檢視、傾斜檢查。
5. 漸層、霧氣、光暈、剪影、需要精確對齊的東西,仍然用 SVG 畫,不要浪費生成次數。

一張五層的桌布大約是 1 張母片 + 4 到 5 張圖。以 Gemini 3.1 Flash Image(2K)計,約 US$0.5;
用 Nano Banana 2.1 約 US$0.25。助手面板下方會顯示本次對話生成了幾張圖。

## 驗證情況

- 已驗證(自動化測試,`node tests/providers.test.js`):兩家圖片模型的請求格式、
  Gemini 會略過「思考中」的過渡圖、綠色主體改用洋紅背景、OpenAI 有參考圖時改走 edits 端點。
- 已驗證(瀏覽器,用假的圖片產生器):生成 → 色鍵去背 → 放成圖層 → 檢視的整條流程,
  以及色鍵去背的結果:綠底上的紅色圓環,外圍和環中間的綠色都去掉,環內另一塊較深的綠色保留。
- **沒有驗證**:用真的金鑰呼叫任何一家圖片模型。請求格式是照官方文件寫的,模型名稱和價格
  取自 2026 年 11 月的文件,之後可能改名或調價。實際生成的風格一致性如何,要用了才知道。

## 已知限制與下一步

- **一致性靠參考圖,不是保證。** 模型有時還是會畫出不同畫風,需要重來。
- **色鍵去背對半透明物體無效。** 可以改接專門的去背模型;App 專案已經在用 ONNX Runtime,
  同樣的方式可以在瀏覽器裡跑小型去背模型,不需要金鑰。
- **做法 D(一張圖切層再補洞)值得做。** 流程是:生成一張完成圖 → 用景深模型得到景深圖 →
  依深度切成幾層 → 每一層被切掉的地方請圖片模型補畫。一致性最好,成本也可能更低。
- **動態素材。** App 支援影片圖層,影片生成模型可以產生會動的背景(雲、水面)。成本高很多,先不做。
